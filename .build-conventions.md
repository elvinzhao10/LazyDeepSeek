# LazyDeepSeek Build Conventions (SHARED — every build agent MUST read this first)

LazyDeepSeek is the **DeepSeek Harness member of the LazySeries family**, produced as a
rename-port of **LazyQoder** (previous base v1.3.0; v1.3.1 surgical fix round;
lineage: LazyZCodex → LazyTrae → LazyBuddy
→ LazyQoder → LazyDeepSeek). Output lives ONLY under
`/Users/Admin/Desktop/lazyseries/lazydeepseek/`. The source repos
(`lazyqoder/`, `LazyTrae/`, `LazyBuddy/`, `lazykimi/`) under
`/Users/Admin/Desktop/lazyseries/` are READ-ONLY — never modify them.
Research material for this port lives in `.study/` (never shipped).

## Rename map actually applied (LazyQoder → LazyDeepSeek for DeepSeek Harness)

- `lazyqoder` → `lazydeepseek` (identifiers, filenames, state dir `.lazyqoder/` → `.lazydeepseek/`)
- `LazyQoder` → `LazyDeepSeek`, `LAZYQODER` → `LAZYDEEPSEEK` (product/machine names)
- `QODER_PLUGIN_ROOT` → `CLAUDE_PLUGIN_ROOT` (DeepSeek Harness expands `${CLAUDE_PLUGIN_ROOT}`
  in plugin hooks and plugin `.mcp.json`; `${LAZYDEEPSEEK_PLUGIN_ROOT}` is an alias)
- `QODER_PROJECT_DIR`/`QODER_PLUGIN_DATA` → the then-host project/plugin-data env tokens
  (both retired again by the dsh port; see the lazyzcode → lazydeepseek map below)
- `qodercli` / `QoderCLI` → `dsh` (host CLI binary), `Qoder` → `DeepSeek Harness` (host display name)
- `lazyqoder-plugin/` path references → `plugins/lazydeepseek` (the DeepSeek Harness plugin is
  nested one level deeper: the market root is `<repo>/plugins/`)
- `codebuddy`/`CODEBUDDY` residues → `dsh`/`DeepSeek Harness`/`CLAUDE_*` (family rename residue)
- The Qoder CLI-only manifest `.qodercli-plugin/` and host mirror `.qoder/` are
  retired (historical). On DeepSeek Harness there is NO plugin manifest file at
  all: the package boundary is the root `package.json` (`dsh` key pointing at
  `cordis.patch.yml`, exact peer pin `@deepseek-ai/dsh 0.2.0-rc.2`, no
  install-time build scripts) plus the committed prebuilt `lib/index.mjs`.
  The plugin-root `.mcp.json` is the typed declaration source for validators;
  the live MCP surface is the six `dsh-mcp-client` stdio rows in the patch.
- Skill/command names keep the `lazy-` prefix (`/lazy-ulw-plan`, 19 skills,
  20 commands); agents are `lazydeepseek-<role>`; scripts are `lazydeepseek-*`.

## What is intentionally NOT byte-identical (per-host, by design)

- `contracts/dsh-route-contract.v1.json` — the dsh distribution routes (ratified
  Q1, GitHub-only; the npm registry is NOT used for this package):
  `dsh-plugin-git-sha` (default; git spec pinned to a commit sha),
  `dsh-plugin-tarball` (alternate; GitHub release asset),
  `dsh-plugin-local-dir` (development), and `manual-skills-mcp-fallback`
  (recovery-only; excludes commands/agents/hooks). Payload inventory is
  regenerated with
  `node plugins/lazydeepseek/scripts/lazydeepseek-regenerate-route-contract.js`
  after ANY edit under skills/, commands/, agents/, hooks/, mcp/, or `.mcp.json`
  (run from the repo root; it also refreshes the `.sha256` sidecar).
- `contracts/dsh-hook-consumers.v1.json` — the dsh hook surface: FIVE events
  bridged 1:1 through `@deepseek-ai/dsh-hooks-claude-code`
  (SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, Stop) and TWO
  synthesized (PermissionRequest folded into the PreToolUse handler,
  PostToolUseFailure discriminated inside PostToolUse — both marked degraded;
  native waterfall replacements are the named native-ize follow-up). The
  generated bridge config is `$DSH_HOME/lazydeepseek/hooks.dsh.json`.
- `contracts/lazy-harness-lifecycle.v1.schema.json` — host enum carries `dsh`
  (single host), product enum carries `LazyDeepSeek`; digests are pinned in
  `scripts/lifecycle/bootstrap.js` and mirrored in the `.sha256` sidecars.
- Hook scripts emit DeepSeek Harness-safe stdout: either valid JSON
  (`{"additionalContext": "..."}`) or NOTHING; deny = exit 2 with stderr reason.
  Diagnostics go to stderr, never stdout.

## DeepSeek Harness-host facts every agent must respect

- Install/update/removal happen through the dsh CLI plugin verbs:
  `dsh plugin --profile <name> add github:<org>/LazyDeepSeek#<sha>` (default
  git-spec route), a pinned GitHub release tarball (alternate), or `./lazydeepseek`
  local-dir (development). There is NO marketplace and no host-side plugin
  manifest; discovery is the GitHub repo (topic `dsh-plugin`). Inspect the
  composed config with `dsh --profile <name> --dump-config`; headless CI:
  `dsh --profile <name> "<task>"` (exit 0 = completed turn).
- Project memory is `AGENTS.md` (workspace) + `~/.dsh/AGENTS.md` (user);
  the family's `workbuddy.md` pointer convention maps to AGENTS.md.
- dsh tool names are LOWERCASE (read, bash, write, edit, subagent, skill,
  todo_write); hook matchers are case-sensitive regexes over those names
  (`write|edit|bash`, never `Write|Edit|Bash`). Agents restrict tools via
  preset `toolFilter` (dsh has no agent-markdown frontmatter loading); the
  checked-in `agents/*.md` files are the preset source, not a loadable surface.
- The MCP profile gate (`mcp/profile-gate.sh`) defaults unset/empty
  `LAZYDEEPSEEK_MCP_MODE` to `orchestrated` so all six declared servers stay
  active out of the box; genuinely deferred servers exit 0 quietly.

## Verification discipline

- Package: `bash plugins/lazydeepseek/scripts/lazydeepseek-load-check.sh` →
  `PACKAGE_READINESS=full`.
- Aggregate: `LAZYDEEPSEEK_VERIFY_SUITE=all bash plugins/lazydeepseek/scripts/lazydeepseek-verify.sh`
  (core | lifecycle | all; doctor, smoke, docs, security, mcp-test,
  hook-pipeline, load-check, contract-check, shell regressions, node tests,
  pytest).
- Naming: `node scripts/check-product-naming.js`.
- Python: 3.10+ syntax is used throughout; scripts resolve `python3.13`–
  `python3.10` when the system `python3` is older (or set `LAZYDEEPSEEK_PYTHON`).
- Release gates: `bash plugins/lazydeepseek/tests/publication-regression.sh`,
  `node scripts/check-product-naming.js`, tag `vX.Y.Z` only after green CI.
