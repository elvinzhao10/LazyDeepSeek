## Role migration and evidence

The previous 13 `@deepseek-ai/dsh-tool-subagent` rows supplied `persona` and `toolFilter`, which [tagged upstream source](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.3/packages/subagent/tool-subagent/src/index.ts) rejects at activation. The published rc.2 package has the same guard; a schema-only check had missed it. The package now selects 13 Agent Presets preserving the original persona hashes and tool allowlists. The [filesystem plugin](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.3/packages/fs/tool-fs/src/index.ts) selects read/write/edit independently. The [jobs plugin](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.3/packages/jobs/tool-jobs/src/index.ts) registers three tools together, so a scoped facade forwards only `job_output`. A scoped deny mask tracks changes in inherited global tools and leaves the parent registry untouched. The web profile retains its existing preset registry; base-backed profiles receive a fallback registry if one is absent.

An isolated rc.3 SDK fixture mounted each preset on a real Agent and compared its visible tools and persona hash to the prior role contract. Separate checks covered late allowed and forbidden global tools, parent isolation and scope disposal. Temporary DSH homes booted web, headless, SDK and ACP compositions without activation warnings; `sdk-minimal` lacks required services and is unsupported. These checks did not execute an actual model-backed delegation or establish a current user host session.
